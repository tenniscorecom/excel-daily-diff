# 仕様書

このツールの処理仕様（保守する人向け）。コーディング規約は comken リポジトリの
`CONVENTIONS.md` と `docs/プロジェクト規約.md` に従う。

---

## 1. 目的・概要

同じフォルダに毎日たまっていく `一覧_YYYYMMDD.xlsx` を、**隣り合う日どうしで順に
突き合わせて、日ごとの増減を出す**ためのツール。

条件に合う行を「顧客番号」で突き合わせ、次の2つを数える。

| 判定 | 意味 |
|---|---|
| **延期** | 前日にあって当日にない = その案件が対象月から外れた |
| **積み上げ** | 前日になくて当日にある = 対象月の中へ入ってきた |

元ファイルは1ファイルで数万行ある。全列を比較すると重いので、**差分は顧客番号の
有無だけで判定する**（列の値の変化は見ない）。

> [!important] 日付が2種類出てくる
> 混同しやすいので先に区別しておく。
>
> | 呼び名 | どこで使うか | 設定 |
> |---|---|---|
> | **業務日**（= ファイル名の日付 - 1日） | **集計表の横軸**。いつ時点の一覧かを表す。**対象月もこの業務日で決める** | 入力フォルダの最新ファイルの日付で自動。`config.ini` からは変えない |
> | **案件の日付**（DATE_COLUMN） | **絞り込みだけ**。対象月に入っているかを見る | 業務日と `NEXT_MONTH_FROM_DAY`（既定23）で自動。`config.ini` からは変えない |
>
> 入力ファイル `一覧_YYYYMMDD.xlsx` は「前日終了時点」のデータなので、横軸は
> **ファイル名の日付 - 1日** = 業務日にずらす。たとえば `一覧_20260825.xlsx` の
> 中身は 8/24 終了時点の状態を指し、前日ファイルとの差分は「8/24 に動いたぶん」を
> 表すので、業務日 8/24 の列に記録する。混同防止のため、ログでは業務日と
> ファイル名の両方を併記する。
>
> この2つを1つの設定で兼ねていた時期があり、**積み上げだけが0件になる**不具合を生んだ。
> 積み上げ（新しく入ってきた案件）は先の日付を持つため、横軸の終わりで絞ると
> 全部範囲外に落ちる。延期は過去の日付を持つので残る。非対称に0になるのはこれが原因だった。
> 今は両方を **実行時** に決めているので、`config.ini` でこの2つを別々に指定する手段は無い。

## 2. 処理フロー

```
入力: [FILES] INPUT_FOLDER にある 一覧_*.xlsx のうち、
      既存 CSV があれば最後の業務日の次の業務日から、入力フォルダ内の最新ファイルまで
      （既存 CSV が無い、または絞り込み条件が変わった場合は最も古いファイルから全期間）
  ↓
絞り込み: 3条件すべてに当てはまる行だけを残す（3章）
  ↓
突合: 日付順に並べ、隣り合う組ごとに顧客番号の集合を比べる
        前の日のみに存在 → 延期
        後の日のみに存在 → 積み上げ
      結果は「業務日（= 後ろ側のファイル日付 - 1日）」の列に入る
  ↓
出力: 集計.csv 1本（OUTPUT_FOLDER に毎回上書き）
```

**集計対象月は業務日から決める**（`src/run.py` の `_target_months`）。業務日 D の
列は D の月で案件を絞り、**23日以降なら D の翌月も対象**になる（12月の翌月は翌年の1月）。
**これは「1月の列は 1月の案件について見たい」という集計意図に沿うためで、実行日が
8月でも業務日 1月の列は 1月の案件だけを対象にする。** 実行日（= ツールを起動した日）
は見ず、業務日（= ファイル名の日付 - 1日）だけを見る点が旧仕様と異なる。

**横軸の期間（業務日 開始日〜終了日）は、毎回実行時に既存 CSV から決める**（`src/run.py`）。
条件が変わったときだけ全期間を作り直し、そうでなければ「既存 CSV の最後の業務日の
次の業務日」からの増分だけ計算する。**開始日を `config.ini` から指定する手段は無い**
（旧 `[FILES] START_DATE` / `END_DATE` は廃止）。

**読み込むのは今年の1月1日から今日までの範囲だけ**（`src/run.py` の `_range_floor`）。
入力フォルダに何年ぶんファイルが溜まっていても、この範囲の外は開かない（古いファイルは
シート名が「一覧」ではなかったりして構造が違うことがあるため）。範囲の最初の1ファイルの
比較相手として、範囲外の**直前1ファイルだけは例外的に読む**（存在すれば）。1月に実行した
ときは、前年12月のファイルが比較相手として1件だけ読まれる。

**範囲の初日を出すには、その手前のファイルが要る**ので1件だけ余分に読む
（`src/run.py` の `_files_in_range`）。範囲の外まで読むと数万行 × 日数ぶん無駄になるため、
必要な範囲だけに絞っている。

土日祝でファイルが飛んでいる日は、**飛んだ手前のファイルが比較相手**になる。
ファイルが無い日の列は、件数0と区別できるよう**空セル**にする。

### 絞り込みの基本3条件

1. `[SOURCE] DATE_COLUMN`（既定「予定日」）の**年月が業務日 D の対象月と一致**する
   （対象月は業務日基準。業務日が23日以降なら翌月も含む）
2. `[SOURCE] PLAN_COLUMN`（既定「種別」）が `PLAN_PREFIXES` のいずれかで**始まる**
3. `[SOURCE] KIND_COLUMN`（既定「状態」）が `KINDS` のいずれかと**完全一致**

「予定日」列は Excel の日付型でも文字列でも読める（`src/source.py` の `DATE_TEXT_FORMATS`）。
値が入っているのに日付として読めない行は、件数を WARNING に出して集計から外す。

### あとから足す絞り込み（コードを直さずに増やせる）

「地域に離島が入っていないもの」のような条件は、**config.ini にセクションを書くだけ**で足せる。
4つのセクションが演算子に対応する（`src/source.py` の `load_rules`）。

| セクション | 意味 |
|---|---|
| `[INCLUDE_CONTAINS]` | その列に語が**含まれる**行だけ残す |
| `[EXCLUDE_CONTAINS]` | その列に語が**含まれる**行を外す |
| `[INCLUDE_EXACT]` | その列が語と**完全一致**する行だけ残す |
| `[EXCLUDE_EXACT]` | その列が語と**完全一致**する行を外す |

```ini
[EXCLUDE_CONTAINS]
地域 = 離島, 山間部
```

- 1行が `ColumnRule`（列名・語・含む/一致・残す/外す）1件になる
- 同じ行に並べた語は **OR**（どれか1つでも当てはまれば該当）
- 列・セクションをまたいだ条件は **AND**（すべて満たす行だけ残る）
- **書かれていないセクションは条件なしとして飛ばす**（`ConfigSectionNotFoundError` を捕まえて空扱い）
- **ルールに書いた列も見出しの検証対象**にする。列名を打ち間違えたときに
  「1件も除外されない」「全部消える」と静かに間違うのではなく `ExcelColumnNotFoundError` で止める
- 読み込んだルールは INFO ログに「地域 が 離島 を含む行を外す」の形で出す
- 値は**角括弧なしのカンマ区切り**（`地域 = 離島, 山間部`）と comken 形式の
  `[離島, 山間部]` の両方を受ける。comken の `_parse_value` は角括弧付きしか
  list にしないため、`_to_words` 側でカンマ分割している
- **比較は大文字小文字・全角半角を区別する**（`normalize` を通していない）。
  区切りにカンマを使うので、カンマを含む語は指定できない
- **列名に `・`・全角括弧・スペースが入っていてもそのまま書ける**（configparser は
  最初の `=` までをキー名にするため、使えないのは `=` だけ）。
  読み取り側は**見出しの前後の空白を落としてから照合する**——Excel の見出しには
  `備考 ` のように空白が紛れ込むことがあるが、configparser がキー名の空白を落とすので
  config.ini 側に空白付きの列名を書く手段がなく、そのままでは一致させられない

演算子を増やしたいときは `[SOURCE]` 側ではなく `src/source.py` の `load_rules` に
セクションを1行足す。`PLAN_PREFIXES`（前方一致）だけはこの仕組みに寄せていない——
**CSV の「種別」列の並び順を兼ねている**ため。

## 3. 入出力

| 種別 | 内容 | 場所 |
|---|---|---|
| 入力 | `一覧_YYYYMMDD.xlsx`（既存 CSV の最後の業務日+1日 〜 入力フォルダ内の最新ファイル。条件が変わった場合は最古ファイルから全期間） | config.ini `[FILES] INPUT_FOLDER` |
| 出力 | `集計.csv`（対象月×種別×判定 の行 × 業務日列。毎回上書き） | config.ini `[REPORT] OUTPUT_FOLDER` |
| 補助出力 | `集計.conditions.txt`（今回使った絞り込み条件を人が読めるテキストで保存） | config.ini `[REPORT] OUTPUT_FOLDER`（CSV の隣） |

### 出力レイアウト（`集計.csv`）

| 対象月 | 種別 | 判定 | 2026-04-21 | 2026-04-22 | … | 2026-08-12 |
|---|---|---|---|---|---|---|
| 2026-04 | 標準 | 積み上げ | 3 | 1 | | |
| 2026-04 | 標準 | 延期 | 1 | 0 | | |
| 2026-04 | 上位 | 積み上げ | 1 | 0 | | |
| 2026-04 | 上位 | 延期 | 0 | 2 | | |

- 行は **対象月 × 種別 × 判定（積み上げ／延期）**。対象月が変わっても古い対象月の
  行はそのまま残す（新しい日付列はその行では空セルになる）
- 列見出しは **業務日**（= ファイル名の日付 - 1日）の `YYYY-MM-DD` ISO 形式
  （増分計算で読み戻すために年が要る）。入力ファイルが「前日終了時点」のデータなので、
  ファイル名より1日早くしている
- **列は開始日から終了日まで1日も飛ばさず並べる**
- ファイルがあった日でも件数が 0 なら **`"0"`** を入れる（空白と区別するため）
- **業務日が無い日は空セル**（件数0と比較できなかったことを示す）
- **業務日 23日以降を含む業務日範囲では、当月と翌月の両方の行が生成される**
  （対象月は業務日基準。実行日ではなく業務日で判定する）

## 4. 設定（config.ini）

| セクション | キー | 意味 |
|---|---|---|
| `[FILES]` | `INPUT_FOLDER` | `一覧_YYYYMMDD.xlsx` が並んでいるフォルダ |
| | `FILE_PATTERN` | 読み取るファイル名のパターン（既定 `一覧_*.xlsx`） |
| `[SOURCE]` | `SHEET_NAME` / `HEADER_ROW` | 読み取り元のシート名と見出し行 |
| | `KEY_COLUMN` | 突き合わせるキー列（既定「顧客番号」） |
| | `DATE_COLUMN` | **対象月かどうかを見る列**（既定「予定日」） |
| | `PLAN_COLUMN` / `KIND_COLUMN` | 絞り込みに使う列 |
| `[FILTER]` | `PLAN_PREFIXES` | 対象にする種別の先頭語。**CSV の「種別」列の並び順にもなる** |
| | `KINDS` | 対象にする状態 |
| `[REPORT]` | `OUTPUT_FOLDER` | 出力先フォルダ（`集計.csv` と `集計.conditions.txt` の置き場所） |
| `[EXCLUDE_CONTAINS]` 他3種 | `列名 = 語, 語` | あとから足す絞り込み（任意。上の「あとから足す絞り込み」参照） |

> **集計対象月と横軸の期間は、`config.ini` からは指定しない。**
> 対象月は業務日から、横軸は既存 CSV の最後の日付から自動で作る（処理フロー参照）。
> 旧 `[FILTER] TARGET_MONTH` / `[FILES] START_DATE` / `END_DATE` は廃止済み。

## 5. 構成

```
main.py            エントリポイント（ログ設定 → run → エラー受け）
config.ini         設定（.gitignore。初回実行時に example から作られる）
実行.bat           起動用（ターミナルから叩く。`pause` 無し＝無人実行向け）
src/
  run.py             処理の流れ（対象月決定 → 期間計算 → 突合 → CSV 出力）
  source.py          入力ファイルを読み、条件に合う行を {顧客番号: Record} にする。load_rules もここ
  diff.py            日付順のファイルを隣り合う組で突き合わせて Counts にする
  report.py          集計.csv の読み書き（既存行のマージ、空セルと "0" の区別）
docs/
  使い方.md         操作手順（非エンジニア向け）
  仕様書.md         この文書
  ERRORS.md         エラー対応
```

comken は共有サーバーを直接参照する（`実行.bat` が起動時に `PYTHON_LIBRARY` を `PYTHONPATH` に足す）。

## 6. 判断の記録

- **顧客番号が重複していたら、先に出てきた行を採用**して WARNING に件数を出す。
  差分はキーの有無で決まるので、どちらの行を採っても延期・積み上げの判定は変わらない
  （変わるのは集計表のどの日付に数えるかだけ）。数万行のうち1件の重複で処理全体を
  止める方が実務では困るため、例外にはしない
- **`comken.utils.diff_rows` は使っていない。** 追加・削除に加えて変更も検出する関数で、
  数万行 × 全列の突き合わせが走る。ここで欲しいのはキーの出入りだけなので集合演算にした
- **入力は `Excel(path, read_only=True)` の `read_computed_rows_as_dicts` で読む。**
  見出し行をキーにした辞書のリストが返る（旧 `ExcelReader.iter_rows` は1行ずつの
  ストリーミングだったが、現行 API にはストリーミングの入口が無いため全件を
  メモリに載せる）。そのうえで「条件を満たす行だけを突合用の辞書に残す」という
  元の意図は変わっていない
- **整数の数値セルは文字列と同じIDに正規化する。** たとえば数値 `1001` と文字列
  `"1001"` は同じ顧客番号として突き合わせる
- **日付の列は期間の全日を並べる。** 件数0の日を詰めると、日付の間隔が飛んで
  前後の週と見比べられなくなるため
- **絞り込みの日付と横軸の日付を分けた。** 当初は1つの設定で
  兼ねていたが、**積み上げだけが0件になる**。積み上げ（新しく入ってきた案件）は
  先の日付を持つため、横軸の終わりで絞ると全部落ちる。延期は過去の日付なので残る
- **読み込みは1ファイル1回。** 隣り合う組を順に比べるので、前回読んだ結果を
  次の比較の「前の日」として使い回す（`src/diff.py`）
- **横軸の範囲＋1件だけ読む。** 範囲外のファイルまで読むと、数万行 × 日数ぶんの
  読み込みが丸ごと無駄になる
- **読み込み範囲は今年の1月1日からにした。** 業務として「今年に入ってから当月ぶんの
  積み上げ・延期がどう動いてきたか」を見る必要があるため。下限は実行年で決まり、年が
  変わると自動的に新しい年の1月1日に切り替わる（増分実行では前年の列がそのまま残る
  が、絞り込み条件を変えて作り直すと前年の列は消える）。**初回実行と条件変更時は
  1年ぶんのファイルを読むことになるため時間がかかる**
- **出力を Excel から CSV に変えた。** 内訳シート相当を廃止し、集計シート相当を
  `集計.csv` 1本に出している（毎回上書き）。集計対象月の行を縦に並べ、業務日を
  列に並べる形に変えたため、シートを分ける必然性が無くなった
- **集計対象月は業務日から決める。** 月が変わったら `config.ini` を書き換える運用は
  不要になった。業務日 23日以降は翌月も対象に加え、月末の駆け込みで増えたぶんを
  取りこぼさない。実行日（= ツールを起動した日）は対象月の判定に使わない——
  **業務日 1月の列は 1月の案件について見たい**ため、実行日が 8月でも 1月の
  案件が正しく集計される
- **横軸は業務日ベースにした。** 入力ファイル `一覧_YYYYMMDD.xlsx` は「前日終了時点」の
  データなので、`一覧_20260825.xlsx` の中身は 8/24 終了時点の状態を指す。隣り合う
  2ファイルを比べた結果は「8/24 に動いたぶん」であり、業務日 8/24 の列に入れるのが
  自然。列名とファイル名が1日ずれて見えるのはこのため
- **横軸の期間は既存 CSV から増分計算する。** 毎回全期間を作り直すと日数が伸びるほど
  遅くなる。既存 CSV の最後の業務日 + 1日からの差分だけ計算する（業務日 D の列は
  ファイル日付 D+1 で生成されるため、次に読むファイル日付は D+2）。絞り込み条件が
  変わったときは過去ぶんの数値も変わるので、`集計.conditions.txt` を前回値と比較して
  違ったら全期間を作り直す
- **古い対象月の行は残す。** 月をまたいで起動したとき、前回の対象月ぶんが消えると
  過去との比較ができなくなる。新しい日付列はその行では空セルにして、データが無いことを
  示す（`0` ではない点に注意）

## 7. 実行方法

- 通常: ターミナルで `実行.bat` を叩く（または `python main.py`）
- RPA 基盤から: `実行.bat` を絶対パスで起動する（終了コードで成否を判断する）か、`python <絶対パス>\main.py` を直接呼ぶ
- 動作確認: `main.py` を `with dry_run():` で囲むと、その範囲の保存をスキップできる
