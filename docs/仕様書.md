# 仕様書

このツールの処理仕様（保守する人向け）。コーディング規約は comken リポジトリの
`CONVENTIONS.md` と `docs/プロジェクト規約.md` に従う。

---

## 1. 目的・概要

同じフォルダに毎日たまっていく `一覧_YYYYMMDD.xlsx` を、**隣り合う日どうしで順に
突き合わせて、日ごとの増減を出す**ためのツール。

条件に合う行を「顧客番号」で突き合わせ、次の2つを数える。

| 判定 | 意味 |
|---|---|
| **延期** | 前日にあって当日にない = その案件が対象月から外れた |
| **積み上げ** | 前日になくて当日にある = 対象月の中へ入ってきた |

元ファイルは1ファイルで数万行ある。全列を比較すると重いので、**差分は顧客番号の
有無だけで判定する**（列の値の変化は見ない）。

> [!important] 日付が2種類出てくる
> 混同しやすいので先に区別しておく。
>
> | 呼び名 | どこで使うか | 設定 |
> |---|---|---|
> | **ファイル名の日付** | **集計表の横軸**。いつ時点の一覧かを表す | `[FILES] START_DATE` / `END_DATE` |
> | **案件の日付**（DATE_COLUMN） | **絞り込みだけ**。対象月に入っているかを見る | `[FILTER] TARGET_MONTH` |
>
> この2つを1つの設定で兼ねていた時期があり、**積み上げだけが0件になる**不具合を生んだ。
> 積み上げ（新しく入ってきた案件）は先の日付を持つため、横軸の終わりで絞ると
> 全部範囲外に落ちる。延期は過去の日付を持つので残る。非対称に0になるのはこれが原因だった。

## 2. 処理フロー

```
入力: [FILES] INPUT_FOLDER の 一覧_*.xlsx のうち、
      ファイル名の日付が START_DATE〜END_DATE に入るもの ＋ その1つ前
  ↓
絞り込み: 3条件すべてに当てはまる行だけを残す（3章）
  ↓
突合: 日付順に並べ、隣り合う組ごとに顧客番号の集合を比べる
        前の日のみに存在 → 延期
        後の日のみに存在 → 積み上げ
      結果は「後ろ側のファイルの日付」の列に入る
  ↓
出力: Excel 1ファイル（集計シート + 明細シート）
```

**範囲の初日を出すには、その手前のファイルが要る**ので1件だけ余分に読む
（`src/run.py` の `_target_files`）。範囲の外まで読むと数万行 × 日数ぶん無駄になるため、
必要な範囲だけに絞っている。

土日祝でファイルが飛んでいる日は、**飛んだ手前のファイルが比較相手**になる。
ファイルが無い日の列は、件数0と区別できるよう**空セル**にする。

### 絞り込みの基本3条件

1. `[SOURCE] DATE_COLUMN`（既定「予定日」）の**年月が `[FILTER] TARGET_MONTH` と一致**する
   （範囲ではなく月の一致。翌月は含まない）
2. `[SOURCE] PLAN_COLUMN`（既定「種別」）が `PLAN_PREFIXES` のいずれかで**始まる**
3. `[SOURCE] KIND_COLUMN`（既定「状態」）が `KINDS` のいずれかと**完全一致**

「予定日」列は Excel の日付型でも文字列でも読める（`src/source.py` の `DATE_TEXT_FORMATS`）。
値が入っているのに日付として読めない行は、件数を WARNING に出して集計から外す。

### あとから足す絞り込み（コードを直さずに増やせる）

「地域に離島が入っていないもの」のような条件は、**config.ini にセクションを書くだけ**で足せる。
4つのセクションが演算子に対応する（`src/settings.py` の `_load_rules`）。

| セクション | 意味 |
|---|---|
| `[INCLUDE_CONTAINS]` | その列に語が**含まれる**行だけ残す |
| `[EXCLUDE_CONTAINS]` | その列に語が**含まれる**行を外す |
| `[INCLUDE_EXACT]` | その列が語と**完全一致**する行だけ残す |
| `[EXCLUDE_EXACT]` | その列が語と**完全一致**する行を外す |

```ini
[EXCLUDE_CONTAINS]
地域 = 離島, 山間部
```

- 1行が `ColumnRule`（列名・語・含む/一致・残す/外す）1件になる
- 同じ行に並べた語は **OR**（どれか1つでも当てはまれば該当）
- 列・セクションをまたいだ条件は **AND**（すべて満たす行だけ残る）
- **書かれていないセクションは条件なしとして飛ばす**（`ConfigSectionNotFoundError` を捕まえて空扱い）
- **ルールに書いた列も見出しの検証対象**にする。列名を打ち間違えたときに
  「1件も除外されない」「全部消える」と静かに間違うのではなく `ExcelColumnNotFoundError` で止める
- 読み込んだルールは INFO ログに「地域 が 離島 を含む行を外す」の形で出す
- 値は**角括弧なしのカンマ区切り**（`地域 = 離島, 山間部`）と comken 形式の
  `[離島, 山間部]` の両方を受ける。comken の `_parse_value` は角括弧付きしか
  list にしないため、`_to_words` 側でカンマ分割している
- **比較は大文字小文字・全角半角を区別する**（`normalize` を通していない）。
  区切りにカンマを使うので、カンマを含む語は指定できない
- **列名に `・`・全角括弧・スペースが入っていてもそのまま書ける**（configparser は
  最初の `=` までをキー名にするため、使えないのは `=` だけ）。
  読み取り側は**見出しの前後の空白を落としてから照合する**——Excel の見出しには
  `備考 ` のように空白が紛れ込むことがあるが、configparser がキー名の空白を落とすので
  config.ini 側に空白付きの列名を書く手段がなく、そのままでは一致させられない

演算子を増やしたいときは `[SOURCE]` 側ではなく `settings.py` の `_load_rules` に
セクションを1行足す。`PLAN_PREFIXES`（前方一致）だけはこの仕組みに寄せていない——
**集計表の列グループの並び順を兼ねている**ため。

## 3. 入出力

| 種別 | 内容 | 場所 |
|---|---|---|
| 入力 | `一覧_YYYYMMDD.xlsx`（横軸の範囲＋その1つ前だけ読む） | config.ini `[FILES] INPUT_FOLDER` |
| 出力 | `延期積上集計_(横軸の開始)_(横軸の終了).xlsx` | config.ini `[REPORT] OUTPUT_FOLDER` |

### 出力レイアウト

**集計シート**（件数）

|  | 標準 | | | 上位 | | |
|---|---|---|---|---|---|---|
| | 4/21 | 4/22 | … | 4/21 | 4/22 | … |
| 積み上げ | 3 | 1 | | 1 | 0 | |
| 延期 | 1 | 0 | | 0 | 2 | |

- 1行目に種別名（グループの先頭列にだけ置く。並べ替えの邪魔になるのでセルは結合しない）
- 2行目に**ファイル名の日付**。`[FILES] START_DATE` 〜 `END_DATE` を**1日も飛ばさず**並べる
  （4/21〜8/12 なら114日 × 2種別 = 228列になる）
- 4/21 の列 = 「4/20 のファイル」と「4/21 のファイル」を比べた結果
- **ファイルが無い日は空セル**（件数0と区別するため）
- 上2行は固定表示

**明細シート**（比較日・判定・顧客番号・予定日・種別・状態）
集計シートの件数の内訳。比較日の古い順、その中は積み上げ → 延期の順。
「比較日」は集計シートの列に対応する（`4/21` の列が何件なのかを引くための列）。

## 4. 設定（config.ini）

| セクション | キー | 意味 |
|---|---|---|
| `[FILES]` | `INPUT_FOLDER` | `一覧_YYYYMMDD.xlsx` が並んでいるフォルダ |
| | `FILE_PATTERN` | 読み取るファイル名のパターン（既定 `一覧_*.xlsx`） |
| | `START_DATE` / `END_DATE` | **集計表の横軸**になるファイル名の日付の範囲（`YYYY-MM-DD`） |
| `[SOURCE]` | `SHEET_NAME` / `HEADER_ROW` | 読み取り元のシート名と見出し行 |
| | `KEY_COLUMN` | 突き合わせるキー列（既定「顧客番号」） |
| | `DATE_COLUMN` | **対象月かどうかを見る列**（既定「予定日」） |
| | `PLAN_COLUMN` / `KIND_COLUMN` | 絞り込みに使う列 |
| `[FILTER]` | `TARGET_MONTH` | 対象にする月（`YYYY-MM`）。DATE_COLUMN の年月と一致する行だけ数える |
| | `PLAN_PREFIXES` | 対象にする種別の先頭語。**集計表の列グループの並び順にもなる** |
| | `KINDS` | 対象にする状態 |
| `[REPORT]` | `OUTPUT_FOLDER` | 出力先フォルダ |
| `[EXCLUDE_CONTAINS]` 他3種 | `列名 = 語, 語` | あとから足す絞り込み（任意。上の「あとから足す絞り込み」参照） |

## 5. 構成

```
main.py            エントリポイント（設定読み → run → エラー受け）
config.ini         設定（.gitignore。初回実行時に example から作られる）
実行.bat           起動用（ターミナルから叩く。`pause` 無し＝無人実行向け）
スタブ生成.bat      config.ini から補完スタブを作り直す（任意。普段は main.py を1回動かせば自動生成される）
src/
  run.py             処理の流れ（ファイル選定 → 突合 → 出力）
  settings.py        config.ini を読む唯一の場所
  source.py          入力ファイルを読み、条件に合う行を {顧客番号: Record} にする
  diff.py            日付順のファイルを隣り合う組で突き合わせて DailyDiff にする
  report.py          集計シート・明細シートの書き出し
  exceptions.py      このツール固有のエラー
docs/
  使い方.md         操作手順（非エンジニア向け）
  仕様書.md         この文書
  ERRORS.md         エラー対応
```

comken は共有サーバーを直接参照する（`実行.bat` が起動時に `PYTHON_LIBRARY` を `PYTHONPATH` に足す）。

## 6. 判断の記録

- **顧客番号が重複していたら、先に出てきた行を採用**して WARNING に件数を出す。
  差分はキーの有無で決まるので、どちらの行を採っても延期・積み上げの判定は変わらない
  （変わるのは集計表のどの日付に数えるかだけ）。数万行のうち1件の重複で処理全体を
  止める方が実務では困るため、例外にはしない
- **`comken.utils.diff_rows` は使っていない。** 追加・削除に加えて変更も検出する関数で、
  数万行 × 全列の突き合わせが走る。ここで欲しいのはキーの出入りだけなので集合演算にした
- **入力は `Excel(path, read_only=True)` の `read_computed_rows_as_dicts` で読む。**
  見出し行をキーにした辞書のリストが返る（旧 `ExcelReader.iter_rows` は1行ずつの
  ストリーミングだったが、現行 API にはストリーミングの入口が無いため全件を
  メモリに載せる）。そのうえで「条件を満たす行だけを突合用の辞書に残す」という
  元の意図は変わっていない
- **整数の数値セルは文字列と同じIDに正規化する。** たとえば数値 `1001` と文字列
  `"1001"` は同じ顧客番号として突き合わせる
- **日付の列は期間の全日を並べる。** 件数0の日を詰めると、日付の間隔が飛んで
  前後の週と見比べられなくなるため
- **絞り込みの日付と横軸の日付を分けた。** 当初は1つの `START_DATE`〜`END_DATE` で
  兼ねていたが、**積み上げだけが0件になる**。積み上げ（新しく入ってきた案件）は
  先の日付を持つため、横軸の終わりで絞ると全部落ちる。延期は過去の日付なので残る
- **読み込みは1ファイル1回。** 隣り合う組を順に比べるので、前回読んだ結果を
  次の比較の「前の日」として使い回す（`src/diff.py`）
- **横軸の範囲＋1件だけ読む。** 範囲外のファイルまで読むと、数万行 × 日数ぶんの
  読み込みが丸ごと無駄になる

## 7. 実行方法

- 通常: ターミナルで `実行.bat` を叩く（または `python main.py`）
- RPA 基盤から: `実行.bat` を絶対パスで起動する（終了コードで成否を判断する）か、`python <絶対パス>\main.py` を直接呼ぶ
- 動作確認: `main.py` を `with dry_run():` で囲むと、その範囲の保存をスキップできる
