# 延期積上集計

日付ごとに並んだ `一覧_YYYYMMDD.xlsx` を**隣り合う日どうしで順に突き合わせ**、
**延期**（前の日にあって次の日にない）と**積み上げ**（前の日になくて次の日にある）を、
日ごとに数えて CSV に出します。

毎日更新される一覧から「消えた行」「増えた行」の推移を追う、という形の業務なら
列名を設定で合わせるだけで使えます。

[comken](https://github.com/tenniscorecom/comken)（業務自動化用の共通ライブラリ）を
使った利用プロジェクトの例でもあります。

## 特徴

- **列名・シート名・絞り込み条件を `config.ini` から変えられる。** 読み取り元が変わっても
  コードを直さない
- **対象月は業務日で決まる。** 集計表の横軸である業務日（= ファイル名の日付 - 1日）の
  月をそのまま対象月にする。実行日が何月であっても、業務日 1月の列は 1月の案件だけを
  対象にする。**これは「1月の列は 1月時点の案件の積み上げ・延期を見たい」という
  集計の意図に沿うため**
- **横軸の期間は `config.ini` からは指定しない。** 既存の `集計.csv` の最後の業務日の
  次の業務日から、入力フォルダの最新ファイルまで自動で計算する
- **読み込むのは「今年の1月1日 〜 今日」の範囲だけ。** 入力フォルダに何年ぶんファイルが
  溜まっていても、**この範囲の外は開かない**（古いファイルはシート構造が違うことが
  あるため）。範囲の最初の1ファイルに限り、比較相手として範囲外の直前1ファイルだけ読む
- **絞り込み条件を変えたら `集計.csv` を消してから実行する。** 条件変更を自動では
  検知しないため、過去ぶんの数値が古い条件で書かれたまま残らないように、実行前に
  CSV を消す運用が必要。出力の行・列構成が大きく変わったときも、古い形式の
  `集計.csv` を引き継ぐと整合性が崩れるので同様に削除→作り直しが必要
- **絞り込みは後から足せる。** `[EXCLUDE_CONTAINS]` などに `列名 = 語` を1行書くだけ
  （含む／完全一致 × 残す／外す の4種類）
- **列名を打ち間違えたら実行時に止まる。** 黙って0件になったり全部消えたりしない
- 1ファイル数万行を想定し、1行ずつ読む（全件をメモリに載せない）
- **1日ぶん終わるたびに CSV を途中保存する。** 長い処理の途中で落ちても、そこまでの
  分はファイルに残っている（再実行で続きから再開できる）
- 出力は **`集計.csv` 1本**（毎回上書き。日付入りのファイル名は付かない）

## 読み込み範囲について

- 初回は**今年の1月1日からの全ファイルを読むため時間がかかる**（最大で約240件）。
  日々の実行は増分計算なので、遅いのは最初だけ
- **年が変わると下限も新しい年の1月1日に切り替わる。** 増分実行では前年の列がそのまま
  残るが、絞り込み条件を変えて CSV を消して作り直すと前年の列は消える

## 出力の形

`集計.csv` は次の形。**行が「当月/来月 × 判定」の固定 4 行**、**列が業務日**（= ファイル名の日付 - 1日）。
種別（標準/上位）の内訳行は無く、合算のみ。「対象月」列の中身は実際の暦月ではなく
業務日基準の相対ラベル **`当月`** / **`来月`**。

| 対象月 | 判定 | 2026-04-21 | 2026-04-22 | … |
|---|---|---|---|---|
| 当月 | 積み上げ | 3 | 1 | |
| 当月 | 延期 | 1 | 0 | |
| 来月 | 積み上げ | 1 | 0 | |
| 来月 | 延期 | 0 | 2 | |

- **列見出しは `YYYY-MM-DD`**（増分計算で読み戻すために年が要る）
- **列は業務日**（= ファイル名の日付 - 1日）で、入力ファイルが「前日終了時点」のデータであることから
  1日 ずらしている。一覧_20260825.xlsx と 一覧_20260824.xlsx の差分は「8/24 に動いたぶん」を表すので、
  業務日 8/24 の列に記録される
- **列は開始日から終了日まで1日も飛ばさず並べる**。横軸は `集計.csv` の最後の業務日の
  次の業務日から入力フォルダの最新ファイル日まで（既存 CSV が無ければ最古ファイルから）
- **業務日が無い日は空セル**、`0` は「ファイルはあったが件数が0だった」を意味する
- **対象月は業務日で決まる。** 業務日 1月の列は 1月の案件だけを対象にする。実行日が
  何月でもこのルールは変わらない
- 年次累積モードでは「来月」行は構造上常に存在するが、実データは入らない（月末
  lookahead はローリングモード固有の挙動）。ローリングモードで月末近くになった日
  だけ「来月」行にデータが入る

## セットアップ（初回だけ）

1. `実行.bat` を1度動かす（または `python main.py` を実行する）。`config.ini.example` から `config.ini` が作られるので、値を書き換える

comken の場所（`実行.bat` の `PYTHON_LIBRARY`）は作成時に入っているので、通常は触らなくてよい。
comken を別の場所へ移したときだけ、`実行.bat` と `.vscode/settings.json` の**2つ**を直す
（前者は実行用、後者は VS Code の補完・定義ジャンプ用。片方だけ直すと、動くのに補完が効かなくなる）。

## 実行

**人が手で動かすとき**は、ターミナルで `実行.bat` を叩く（または `python main.py`）。
`実行.bat` には `pause` を入れていないので、画面は一瞬で閉じる。

**RPA 基盤から動かすとき**は、`実行.bat` を絶対パスで起動する形と、
`python <このフォルダ>\main.py` を直接呼ぶ形のどちらも使える。`実行.bat` は
終了コードをそのまま返すので、成否を判断できる（`pause` を入れないのは、
無人実行で止まらないようにするため）。
